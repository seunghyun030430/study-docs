# CLAUDE.md

## 이 레포의 목적

"Istio 서비스 메시"를 입문자 관점에서 정리하는 문서 중심 저장소다. 코드 프로젝트가 아니라 지식 정리/문서화가 핵심이며,
정확성과 출처가 코드 실행보다 우선한다.

- 범위: 개념 / 아키텍처 / 데이터 플레인 모드(Sidecar vs Ambient) / 사용법 / 이슈·한계
- 기준 버전: Istio 1.31.x, Kubernetes Gateway API v1.6.0 (조사 기준일 2026-10-08)
- 예제: `examples/` — kind 클러스터 + `istioctl` + YAML 매니페스트

> 정리할 구체적 범위는 사용자가 지정한다. 임의로 문서를 양산하지 말 것.

## 작성 원칙

- **사실 기반**: 사실 주장에는 1차 출처(istio.io 공식 문서·GitHub·Envoy 문서) URL을 함께 단다.
- **추측 금지**: 확신이 없으면 "확인 필요" 또는 "모름"으로 명시.
- **결론 우선**: 결론을 먼저, 근거를 뒤에.
- **비교는 표로**: 선택지·개념이 여러 개면 비교표로.
- **균형**: 권장 사항뿐 아니라 안티패턴·한계·주의사항도 함께.
- **용어**: 기술 용어·고유명사는 원문 그대로(예: sidecar, ztunnel, waypoint, xDS), 한글 설명을 곁들인다.
- **버전 명시**: Istio는 릴리스마다 기능 상태(Alpha/Beta/Stable)가 바뀌므로, 버전 의존적인 주장에는 기준 버전을 적는다.

## 문서 컨벤션

- 모든 문서는 Markdown(`.md`). 본문 서술은 한국어, 코드·식별자·고유명사는 원문.
- 파일명은 `0N-<slug>.md` 번호 순.
- 제목 계층은 `#`(문서당 1개) → `##` → `###` 순으로만.
- 문서 첫머리에 `> 한 줄 핵심 요약`, 끝에 `## 출처`와 `*조사 기준일: YYYY-MM-DD*`.
- 날짜는 절대 표기(예: 2026-10-08). 상대 표현 지양.
- 코드블록은 언어를 명시(`yaml`, `bash`).

## 커밋 규칙

- 문서 1개 = 커밋 1개. 메시지는 `docs: <한글 설명>`.
- 관련 파일만 스테이징(`git add <파일>`), `git add -A` 지양.

## 작업 시 주의

- 요청 범위 안에서만 작업. 문서 과잉 생성·과잉 리팩토링 금지.
- 기존 문서를 고칠 때 출처와 사실관계를 먼저 확인하고 수정한다.
- 예제 YAML을 바꾸면 해당 문서(특히 `04-usage.md`)의 스니펫과 일치하는지 함께 확인한다.
